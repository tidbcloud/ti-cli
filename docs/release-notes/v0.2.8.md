# TiDB Cloud CLI v0.2.8

This patch release lets v0.2.7 users refresh the installed `ti-drive9` companion through `ti update`. Release preparation on October 2, 2026 verified the published Drive9 build `c6e057f`.

## What's new

The updated companion includes these upstream Filesystem fixes:

- Fix an avoidable `EAGAIN` (`Resource temporarily unavailable`) when a FUSE directory listing races the mount's first synchronization reset. Directory reads retry once for that specific reset; other errors retain their existing handling. [Drive9 #1012](https://github.com/mem9-ai/drive9/pull/1012)
- Fix layer and checkpoint unmounts that could stall after reads or successfully persisted writes. Preserve pending layer writes during recovery and report incomplete drain, worker failures, and forced termination as unmount failures. [Drive9 #1002](https://github.com/mem9-ai/drive9/pull/1002)

The ti command surface and download sources are unchanged. Installers and `ti update` fetch the current published companion separately from the ti archive, so `c6e057f` is the verified build, not a version pin. Pinning ti to v0.2.8 does not pin Drive9 or roll back its version.

## Upgrade from v0.2.7

Drain FUSE mounts and unmount all active Filesystem and Vault mounts before replacing the binaries. On macOS or Linux with a ti-owned installation, run:

```bash
ti update --check
ti update --target-version v0.2.8
ti --version
"$(dirname "$(command -v ti)")/ti-drive9" version
```

`ti update --check` compares ti versions, not companion versions. If the selected ti version is already installed, `ti update` exits without refreshing the companion. To refresh Drive9 again at the same ti version, rerun the installer after draining and unmounting:

```bash
curl -fsSL https://github.com/tidbcloud/ti-cli/releases/download/v0.2.8/install.sh | sh -s -- --version v0.2.8 --yes
export PATH="$HOME/.ti/bin:$PATH"
ti --version
"$HOME/.ti/bin/ti-drive9" version
```

The same installer command works for a new installation. For a custom installation directory, pass `--install-dir` with that directory.

On Windows, rerun the PowerShell installer because `ti update` cannot replace the running Windows executable:

```powershell
$script = "$env:TEMP\install-ti.ps1"
iwr https://github.com/tidbcloud/ti-cli/releases/download/v0.2.8/install.ps1 -OutFile $script
powershell -ExecutionPolicy Bypass -File $script -Version v0.2.8 -Yes
$env:Path = "$HOME\.ti\bin;$env:Path"
ti --version
& "$HOME\.ti\bin\ti-drive9.exe" version
```
