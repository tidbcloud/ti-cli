# TiDB Cloud CLI v0.2.5

This release adds Starter export task listing and local-target file download, and publishes TiDB Cloud Filesystem access in `gcp-us-east-1`.

## What's new

- New `ti db list-export-tasks` lists export jobs for a Starter cluster. The command is read-only, requires `--db-cluster-id`, and pages through `GET /v1beta1/clusters/{clusterId}/exports` with `--page-size`, `--page-token`, and optional `--order-by`. Structured output uses `export_tasks` and omits cloud-target credentials.
- New `ti db download-exported-data` downloads files from a completed local-target export. It requires `--db-cluster-id` and `--export-id`, writes under `--output-path` (default: the current directory), skips existing files and the backend `metadata` file, and supports `--dry-run` after listing files and before requesting signed URLs. Presigned URLs never appear in output, errors, logs, or telemetry.
- TiDB Cloud Filesystem now includes the built-in `gcp-us-east-1` placement (`https://gcp-us-east1.drive9.ai`). Installers and region validation accept this code. Starter database commands remain limited to the existing AWS and Alibaba Cloud regions.

## Upgrade from v0.2.4

Drain and unmount active Filesystem mounts before replacing `ti` and its bundled `ti-drive9` companion, then run:

```bash
ti update --check
ti update
ti --version
```

New installations can use:

```bash
curl -fsSL https://github.com/tidbcloud/ti-cli/releases/download/v0.2.5/install.sh | sh -s -- --yes
export PATH="$HOME/.ti/bin:$PATH"
ti --version
```

## List and download a Starter export

List export tasks for a cluster. An empty page is valid when no jobs exist:

```bash
ti db list-export-tasks --db-cluster-id <cluster-id>
ti db list-export-tasks --db-cluster-id <cluster-id> --page-size 10
ti db list-export-tasks --db-cluster-id <cluster-id> --query 'export_tasks[].id'
ti db list-export-tasks --db-cluster-id <cluster-id> --output text
```

Download a completed local-target export after inspecting the planned files:

```bash
ti db download-exported-data \
  --db-cluster-id <cluster-id> \
  --export-id <export-id> \
  --output-path ./export \
  --dry-run

ti db download-exported-data \
  --db-cluster-id <cluster-id> \
  --export-id <export-id> \
  --output-path ./export
```

These commands do not create, describe, or cancel export jobs, and they do not download cloud-target exports (S3, GCS, Azure, or OSS).
