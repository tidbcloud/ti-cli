# TiDB Cloud CLI v0.2.11

This release adds `ti exec` for running commands against a TiDB Cloud Filesystem and hardens handling of remote Git metadata. Runtime is available only in AWS `us-east-1` and `us-west-2`.

## Runtime commands

Use your selected Filesystem to read files, run a script, or work with data without managing a separate execution client:

```bash
ti --region aws-us-east-1 exec 'ls -la'
ti --region aws-us-east-1 exec python3 -c 'print("hello from Runtime")'
```

The service chooses the execution backend. Supported shell operations can run through just-bash without starting a sandbox; commands that need an external program use a sandbox. Shell syntax alone does not determine which backend runs the command.

`ti exec` supports a workspace directory, environment variables, read-only execution and a timeout. It streams output and preserves the companion's exit status. Run `ti exec --help` for flags and examples. [ti #79](https://github.com/tidbcloud/ti-cli/pull/79)

### Current validation limit

Preview validation is incomplete. With the companion build below, cancellation in the current test environment can return an unknown outcome (`255`) without confirming whether the command has stopped. Check the Filesystem and command effects before deciding whether to run the command again. Do not treat `255` as confirmation of cancellation.

The release candidate has not passed the complete live release gate. This section must be re-evaluated against the deployed service before publication; unit tests and a successful build do not establish live cancellation behavior.

## Filesystem fixes

Remote Git metadata is validated before it is used to restore local state or resolve a Git directory or pack symlink. Invalid remote paths are rejected instead of being allowed to escape the intended workspace. [ti #81](https://github.com/tidbcloud/ti-cli/pull/81)

## Upgrade from v0.2.10

Drain and unmount active Filesystem and Vault mounts before replacing either binary. On macOS or Linux with a ti-owned installation:

```bash
ti update --check
ti update --target-version v0.2.11
ti --version
"$(dirname "$(command -v ti)")/ti-drive9" version
```

For a new installation or a reinstall, pass the version explicitly:

```bash
curl -fsSL https://github.com/tidbcloud/ti-cli/releases/download/v0.2.11/install.sh | sh -s -- --version v0.2.11 --yes
export PATH="$HOME/.ti/bin:$PATH"
ti --version
"$HOME/.ti/bin/ti-drive9" version
```

Use `--install-dir` to retain a custom installation directory. On Windows, rerun the PowerShell installer; in-place self-update is unsupported:

```powershell
$script = "$env:TEMP\install-ti.ps1"
iwr https://github.com/tidbcloud/ti-cli/releases/download/v0.2.11/install.ps1 -OutFile $script
powershell -ExecutionPolicy Bypass -File $script -Version v0.2.11 -Yes
$env:Path = "$HOME\.ti\bin;$env:Path"
ti --version
& "$HOME\.ti\bin\ti-drive9.exe" version
```

The companion is downloaded separately from mutable Drive9 endpoints. A ti version does not pin or roll back the companion. Report both versions when diagnosing an issue. `ti update` does not refresh only the companion when ti is already at the requested version; rerun the installer to refresh that installation.
